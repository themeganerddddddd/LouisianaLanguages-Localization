Where this ultimately goes

Two submissions, for two different jobs

Apple: ask Apple to add/expand system-language support. Unicode CLDR: standardize and vet the locale data that operating systems and software use.

Recommended order: finish native-speaker review → prepare CLDR core/basic data → open the CLDR path → submit the Apple enhancement request with the public corpus, reviewer evidence, and CLDR status attached.

Use `lou` and `frc`; document what CLDR already has versus what is missing.

Finish Core Data.

Unicode calls for the correct language code, exemplar sets, country/population information, time-cycle information, writing direction, and English language name; plural information is strongly recommended early.

Request Survey Tool access / new-locale handling as needed.

Native speakers who are not part of a Unicode member organization can request guest accounts. If a locale is not present for contribution, request that it be added.

Reach Basic coverage.

Core data is only the first step. Unicode expects active contributors to continue through the Survey Tool and reach the required coverage.

Current timing (September 2026): CLDR 49 is in Resolution/read-only workflow for most contributors. Unicode's Information Hub says it plans to review new DDL locale requests for CLDR 50 starting in September 2026. Check the live Information Hub before filing.
PACKAGE CHECKLIST

What to attach / link

  • Public visual UI corpus and translation site
  • Reviewed `lou` and `frc` UI exports
  • Locale-data export from the Locale & CLDR page
  • Native-speaker reviewer roster, roles, and review dates
  • Kouri-Vini and Louisiana French orthography/terminology guidance
  • Sources for language conventions and community-use evidence
  • Representative screenshots showing the localization in context
  • GitHub repository with a permissive data license
  • CLDR ticket/account/status when available
